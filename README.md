# VOT-CLI Live v2.0.7 — озвучка видео в Windows

**Прежде всего прочитайте [README исходного для нас VOT-CLI Live](https://github.com/fantomcheg/vot-cli-live/blob/main/README.md)**: там описаны инструмент, поддерживаемые сервисы и основные аргументы CLI. Его текст также сохранён в [README-UPSTREAM.md](README-UPSTREAM.md). Этот README описывает изменения и запуск данного форка.

## Цепочка проектов и авторов

1. [FOSWLY/vot-cli](https://github.com/FOSWLY/vot-cli) — исходный CLI, автор Toil (так указано в package.json проекта). FOSWLY — организация, в которой размещён репозиторий.
2. [fantomcheg/vot-cli-live](https://github.com/fantomcheg/vot-cli-live) — форк VOT-CLI от fantomcheg с поддержкой «Живых голосов» Яндекса и объединения видео с переводом.
3. [Airshipster/vot-cli-live-v2.0.7](https://github.com/Airshipster/vot-cli-live-v2.0.7) — этот форк, созданный из репозитория fantomcheg, с изменениями для Windows, перечисленными ниже.

Версия этого форка — **2.0.7**, проверена **2 октября 2026 года**. Это самостоятельная версия доработок, не номер актуального FOSWLY/vot-cli. Форк может отставать от исходных проектов; изменения upstream автоматически не подхватываются. Наличие более новых возможностей проверяйте по ссылкам выше.

## Что изменено в этом форке

- Добавлено интерактивное меню PowerShell: английский → русский, настройка других языков, справка и выход.
- Добавлено автоопределение исходного языка по данным YouTube; если язык неизвестен, в VOT передаётся auto. Можно выбрать исходный язык вручную. Языки озвучки результата: русский, английский и казахский.
- «Живые голоса» Яндекса запрашиваются как в браузерном VOT, с названием и длительностью ролика. Обязательного запроса токена перед запуском нет; готовность конкретного перевода определяет Яндекс. Для английского → русского доступны живые и стандартные голоса.
- Добавлен Microsoft Edge TTS с выбором диктора: для русского — Дмитрий и Светлана. Дикторы выбранного языка загружаются с сервиса. Для озвучки нужны субтитры с временными метками; при необходимости их текст переводится напрямую через Яндекс Браузер. Аккаунт Microsoft и API-ключ не нужны.
- Добавлен вертикальный список доступного качества без ограничения высоты. Для каждого размера кадра (ширина × высота) показываются только варианты H.264, если они доступны; если H.264 для этого размера нет, показываются все доступные кодеки и исходные контейнеры. Поэтому 1440p/2160p могут быть доступны в VP9 и AV1, а 1080p — только в H.264. Разрешение показывается всегда; FPS, битрейт, кодек и контейнер — при различиях между вариантами.
- В списке показывается известный размер исходного видеопотока. Скорость из HLS-манифеста помечена HLS*: это не измеренный средний битрейт и не гарантия большего файла.
- Добавлено управление обложкой: в выборе качества введите **номер, пробел и 000**, например **4 000**, чтобы первым кадром стала обложка YouTube. Без 000 видеопоток сохраняется без перекодирования; с 000 он перекодируется в H.264 с сохранением разрешения, FPS и синхронизации звука.
- Оригинальный звук автоматически скачивается для форматов без аудио. Громкость фона — 15%, перевода — 100%; автоматическая нормализация отключена. Итоговый звук — AAC.
- Готовое видео сохраняется прямо на рабочий стол текущего пользователя: **оригинальное название (Нейроперевод).mp4**. Повторные загрузки получают номер; существующие файлы сохраняются.
- После завершения задания временная папка очищается. Если перенос на рабочий стол не удался, готовый файл сохраняется, и программа показывает его путь.
- Добавлены проценты текущего этапа и приблизительное оставшееся время для скачивания, синтеза Microsoft и сведения звука. Во время подготовки перевода Яндекс показываются прошедшее время и оценка сервиса, если она есть.
- Добавлена подготовка локальных зависимостей: Node.js, yt-dlp, FFmpeg и npm-пакетов; при выборе Microsoft — Python и edge-tts. Загрузки Node.js, FFmpeg, yt-dlp и Python проверяются по SHA-256. Пакеты устанавливаются в папку программы. Старые компоненты обновляются до проверенных версий.
- Добавлен скрипт создания ярлыка на рабочем столе. Пользовательские пути определяются через Windows; имя пользователя компьютера в исходниках не задано.

Подробности находятся в [LOCAL-CHANGES.md](LOCAL-CHANGES.md). Настройка Microsoft в исходном аддоне VOT относится к переводу текста; Microsoft TTS в этом форке добавлен отдельно через [edge-tts](https://github.com/rany2/edge-tts).

## Запуск

Требуется Windows x64 и PowerShell 7. При необходимости установите PowerShell командой:

```powershell
winget install --id Microsoft.PowerShell -e
```

1. Скачайте и распакуйте этот репозиторий или клонируйте его через Git.
2. Откройте **Start-VOT.cmd**. При первом запуске программа подготовит недостающие компоненты; требуется интернет.
3. Выберите пункт меню, вставьте ссылку на YouTube, выберите языки при необходимости, озвучку и качество. Результат появится на рабочем столе.

В выборе качества **4** означает четвёртый вариант как есть; **4 000** — тот же вариант с обложкой YouTube на первом кадре. Меняется ровно один кадр, длительность ролика и начало звука сохраняются. Изображение вписывается в размер кадра без растяжения; при разных пропорциях добавляются чёрные поля. Такой режим работает дольше и меняет итоговый размер, поскольку видео перекодируется (H.264, CRF 18). Обложка используется только во временной папке и после завершения удаляется вместе с ней.

Первый кадр не гарантирует, что YouTube выберет его как миниатюру после загрузки: для точного выбора используйте [загрузку собственной обложки в YouTube Studio](https://support.google.com/youtube/answer/72431?hl=ru).

### Выбор кодеков и похожие варианты качества

Приоритет H.264 применяется отдельно для каждого разрешения. Если H.264 есть, другие кодеки этого же размера не показываются. Если H.264 нет, доступны все исходные варианты этого размера: например, VP9 и AV1. Все предлагаемые варианты H.264 остаются в списке, включая разные FPS и способы доставки. Для проверенного ролика 1440p и 2160p теперь показаны в VP9/AV1, а 1080p и ниже — в H.264.

Итоговый файл всегда **MP4** с выбранным видеокодеком и звуком AAC. Показанный контейнер относится к источнику: например, WEBM/VP9 перепаковывается в MP4/VP9 без перекодирования изображения. Режим **000** по-прежнему заменяет первый кадр обложкой и перекодирует выбранное видео в H.264.

Два пункта 1080p или 720p могут быть способами доставки одинакового изображения: обычным HTTPS и HLS. У HLS число берётся из BANDWIDTH — заявленной полосы для воспроизведения по [спецификации HLS](https://datatracker.ietf.org/doc/html/rfc8216#section-4.3.4.2), а не из размера готового файла. При проверке двух 1080p-потоков одного ролика меню сообщало 1586 и 3623 кбит/с, но файлы весили 147 285 998 и 147 320 087 байт: разница 34 089 байт. Закодированное изображение совпало после исключения служебных заголовков H.264. Разные цифры здесь не означали разные уровни качества.

```text
1 — Скачать видео: английский → русский
2 — Скачать видео — выбрать другие языки
3 — Показать справку оригинальной утилиты
0 — Выход
```

Для создания ярлыка выполните в папке программы:

```powershell
pwsh -NoProfile -File .\Create-DesktopShortcut.ps1
```

Проверенный набор: Node.js 22.19+, @vot.js/node 3.1.4, @toil/translate 1.10.0, yt-dlp 2026.08.19, FFmpeg 9.0.2; для Microsoft — Python 3.12+ и edge-tts 7.2.8. Системная политика выполнения PowerShell не изменяется. Доступность конкретного перевода зависит от соответствующего онлайн-сервиса.
