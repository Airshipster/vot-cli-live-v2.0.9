# Диагностика VOT-CLI Live

Каждая новая попытка автоматически получает отдельный файл `diagnostic-<идентификатор>.jsonl`. В конце задания выводится строка **«Диагностика: …»**. Для разбора ошибки приложите этот файл; копировать обновления процентов из консоли не требуется.

- Одиночное видео: `%LOCALAPPDATA%\VOT-CLI-Live\diagnostics`.
- Очередь: файл находится рядом с её `report.txt`, в `%LOCALAPPDATA%\VOT-CLI-Live\queues\<очередь>`. Ссылка на последнюю попытку каждого ролика добавляется в отчёт. Предыдущие диагностические файлы при новой попытке не перезаписываются.
- Файл сохраняется после очистки временных видео. Старые журналы эта версия не дополняет задним числом.

## Что записывается

Каждая строка — JSON с UTC-временем `ts`, идентификатором попытки `attempt`, процессом `pid`, номером события внутри процесса `seq` и названием `event`. `elapsedMs` отсчитывается от запуска соответствующего процесса; длительность конкретного запроса или этапа указана отдельно в `durationMs`.

| События | Что по ним проверять |
| --- | --- |
| `attempt.start`, `runtime.start` | Версии приложения, PowerShell, Node.js, SDK, yt-dlp и FFmpeg |
| `metadata.*`, `quality.selected` | Получение доступных форматов, выбранный поток, разрешение и кодек |
| `attempt.settings`, `translation.start` | Языки, голос, источник сохранённого входа и факт передачи доступа — без самого доступа |
| `http.request`, `http.response`, `http.error` | Сервер и операция, длительность, HTTP-код, сетевой код причины; `Retry-After` и идентификатор запроса, если сервер их прислал |
| `translation.response` | Номер опроса, исходный статус SDK, оценка оставшегося времени, наличие полной аудиодорожки |
| `translation.error`, `translation.retry`, `translation.timeout` | Статус сервиса, текст ошибки, число и задержка повторов, исчерпание срока ожидания |
| `upload.*` | Запрошенная Яндексом передача исходной дорожки: размер, число частей, ответы и подтверждение получения |
| `media.download.start`, `media.stream.*`, `tool.*` | Выбранный формат, начало/окончание потока, существенные сообщения yt-dlp, код завершения инструмента, тайм-аут или сигнал остановки |
| `translation-audio.download.*` | HTTP-ответ и полученный объём дорожки перевода |
| `worker.exit`, `cleanup.error`, `attempt.error`, `attempt.finish` | Итог процесса, ошибка очистки/сохранения и подтверждение сохранённого результата |

HTTP-код и статус Яндекса внутри ответа — разные поля. Например, успешный HTTP-ответ ещё не означает готовый перевод: SDK может затем сообщить ошибку авторизации. HTTP 403 на этапе `youtube.media.download` относится к скачиванию исходника, а не к аккаунту Яндекса. Ожидание без готовой дорожки само по себе не считается ошибкой.

Журнал помогает установить этап и наблюдаемый ответ. Сам по себе HTTP 403 не доказывает бан, истечение ссылки или потерю авторизации. Если провайдер не объяснил отказ, внутренняя причина остаётся неизвестной. Отсутствие финальных событий может означать аварийную остановку процесса; точную причину закрытия окна журнал установить не всегда может.

В текущей версии событие `media.stream.progress` раз в 30 секунд сохраняет число байтов, оценку размера и счётчик фрагментов. Это позволяет отличить медленную активную загрузку от отсутствия данных. `null` означает неизвестное значение. У `tool.start` поле `timeoutMs: 0` означает отсутствие общего таймера на скачивание всего видео; сетевой тайм-аут и ограниченные повторы заданы отдельно в `media.download.start`.

В текущей версии событие `media.download.retry` отмечает один повтор после HTTP 403, паузу и точный этап. Сбой скачивания исходника помечается `provider: youtube`, даже если он прервал подготовку перевода. После повторного отказа очередь останавливается; повтор не означает, что сервер обязательно разрешит скачивание.

В текущей версии события `translation.request` и `translation.restart` показывают обычный опрос и единственный запрос нового перевода через штатный параметр SDK `bypassCache`. Перезапуск выполняется после повторяющегося временного отказа сервиса; дальнейший опрос идёт без этого флага. Новый запрос исходной дорожки обслуживается заново, даже если сервер повторно использовал идентификатор задания.

## Исключённые данные

Не записываются тела запросов/ответов, переводимый текст, содержимое видео, токены, Cookie, Authorization, полный набор заголовков или аргументы команд. Записываются только разрешённые HTTP-заголовки. Параметры и фрагменты URL удаляются, пути к медиаресурсам скрываются; Windows-путь профиля заменяется на `%USERPROFILE%`. Из сообщений удаляются известный токен текущего процесса, строки Bearer/Basic и типичные секретные поля. В журнале остаются публичный идентификатор YouTube-видео, технические идентификаторы запросов и параметры обработки.

Диагностика пишет в файл и не добавляет строки прогресса в консоль. История процентов в прежнем консольном журнале сохраняется отдельно.

## Режимы запросов и восстановление

Событие `media.request.policy` содержит режим `gradual` / `preflight`, этап и число одновременных фрагментов. `media.download.retry` отмечает единственный повтор через 30 секунд после HTTP 401/403, с последовательной загрузкой и сохранением выбранного формата. `tool.error.error.httpStatus` сохраняет HTTP-причину, даже если позже возникла вторичная ошибка записи. HTTP-ошибка скачивания YouTube не означает потерю входа Яндекса.

После обычных повторов временного отказа перевода событие `translation.restart` отмечает единственный штатный запрос нового перевода. Ошибка авторизации не запускает это восстановление. Постоянные ошибки сохраняются в отчёте; успешный результат не подставляется.
